## 1. 变体创建与独立流水线（服务端）

### What to build

选题采纳后可再开变体：同选题最多 3 个存活变体（含首个），每个变体是独立内容、走完全独立的研究→内容→四平台→裁判→批准流水线。开变体必填一句「变体假设/角度」，该句写入内容假设字段，并注入 Research Agent 提示词声明与同主题其他变体的差异点；选填受众/漏斗覆盖。变体自动继承选题所属活动，标签按创建序分配 A/B/C。既有「采纳选题」路径同样落库选题关联与首个变体标签。

### Acceptance criteria

- [ ] 既有采纳接口创建的内容带选题关联与变体标签 A
- [ ] 已采纳选题可开变体（≤3 存活），第 4 个被拒并给出明确错误
- [ ] 开变体必填「变体假设/角度」，空值被拒
- [ ] 各变体独立走完整流水线（状态机互不干扰），裁判与人工批准门禁语义与单内容完全一致
- [ ] Research Agent 收到与同主题其他变体的差异声明（mock fixtures 同步）
- [ ] 变体内容的 UTM 归因结构与现状一致（唯一内容 ID + 平台后缀，不回退）
- [ ] 单测覆盖上述全部行为（先设 `PRISM_DATA_DIR` 再动态 import 的既有模式）

### Blocked by

None - can start immediately.

## 2. advance 内容级互斥

### What to build

同一内容的流水线推进在服务端互斥：一个 advance 在执行期间（含 LLM 调用），同内容的再次 advance 立即返回 409「该内容正在执行中」，不触发第二次 Agent 运行；不同内容互不影响。前端沿用现有 busy 禁用，补充 409 错误文案呈现。

### Acceptance criteria

- [ ] 并发 advance 同一内容只触发一次 Agent 运行（mock provider 断言调用次数）
- [ ] 重复请求得到 409 与「该内容正在执行中」信息
- [ ] 不同内容可并发推进
- [ ] 执行完成（含失败）后锁释放，可再次推进
- [ ] 单测覆盖上述行为

### Blocked by

None - can start immediately.（与切片 1 无依赖，可并行）

## 3. 实验对照视图（原型 → 聚合 API → 正式 UI）

### What to build

先出静态 HTML 原型（内容详情页「实验对照」区块 + Topics 页「N 个变体」标识）交用户确认，再实现：按选题分组的变体指标聚合接口（复用现有按内容聚合口径，累计值），正式版前端接入——同选题变体 × 平台指标并排 + 领先摘要（哪个变体、哪个平台、领先多少）。不做观察窗口切片。

### Acceptance criteria

- [ ] 静态原型经用户确认后正式版布局与原型一致（前端先行流程）
- [ ] 聚合接口按选题返回各变体 × 各平台累计指标，JOIN 边界与现有归因口径一致（UTM 精确匹配）
- [ ] 内容详情页显示「实验对照」区块；Topics 页显示「N 个变体」标识
- [ ] 领先摘要数字与表格数据一致
- [ ] 视觉遵循 DESIGN.md；颜色不作唯一信号（状态必带文字）
- [ ] 后端聚合逻辑有单测；`npm run build` 通过

### Blocked by

- 切片 1（要有变体与选题关联才有对照数据）

## 4. 实验结论提议回流假设库

### What to build

对照视图提供「提议实验结论」动作：系统基于变体对照数据生成假设库更新提议（哪条假设被支持/削弱、依据是什么），走既有提议门禁——人工确认后入库、驳回即弃，不新增任何自动写入旁路。选题状态机不新增状态。

### Acceptance criteria

- [ ] 提议生成基于该选题变体的真实对照数据（无数据时给出明确提示而非编造）
- [ ] 提议必经人工确认/驳回（`library_proposals` 既有语义，Agent 只有提议权）
- [ ] 确认后假设库可查到对应记录并可回链到实验
- [ ] 单测覆盖：门禁不可绕过、无数据不生成

### Blocked by

- 切片 3（对照数据聚合是结论生成的输入）
